# VPG08 - AI для команды

Учебный Telegram-бот для групповой переписки: сохраняет сообщения людей, отвечает по контексту при обращении и подводит итоги обсуждения между `/start_listening` и `/stop_listening`.

Используется опыт VPG06 (Haystack + Pinecone + Telegram) и VPG07 (соединение компонентов в пайплайны). Добавлены общая память чата, авторство, сессии и постоянный журнал SQLite.

## Три пайплайна Haystack

| Пайплайн | Соединённые компоненты | Назначение |
| --- | --- | --- |
| Индексация | `OpenAIDocumentEmbedder -> DocumentWriter` | Запись текста и метаданных в `PineconeDocumentStore` |
| Поиск | `OpenAITextEmbedder -> PineconeEmbeddingRetriever` | Поиск до 8 релевантных сообщений в пространстве текущего чата и темы |
| Суммаризация/генерация | `ChatPromptBuilder -> OpenAIChatGenerator` | Итог сессии либо ответ с найденным контекстом |

Все соединения выполнены через `Pipeline.connect`. Каждый граф создаёт собственные экземпляры компонентов. Официальный туториал Extractive QA сохранён в корне как `Pipeline example.ipynb`; источник и контрольная сумма указаны в [TUTORIAL_SOURCE.md](TUTORIAL_SOURCE.md). Из примера использованы принципы сборки графа; extractive reader и локальная модель не запускаются.

## Как устроена память

1. Входящее текстовое сообщение сначала записывается в SQLite с ID сообщения, автором, временем UTC и ID текущей сессии.
2. Затем запускается индексация в Pinecone. При ошибке сообщение остаётся в очереди; повторная запись выполняется на следующем сообщении или через `/sync`.
3. Повторная доставка того же ID не создаёт дубль. Одинаковые фразы разных участников сохраняются отдельно: для обсуждения это разные события.
4. На вопрос бот получает последние 30 сообщений из SQLite и до 8 смысловых совпадений из Pinecone, объединяет их по ID и сортирует хронологически. Это выборка, а не полный архив.
5. Итог сессии строится по всем её сообщениям из SQLite. Поиск top-k не используется как замена полной стенограмме.
6. Состояние сессии и готовое резюме переживают перезапуск. Повторный `/start_listening` не обнуляет активную сессию; повторный `/stop_listening` возвращает сохранённый итог. После ошибки генерации команду завершения можно повторить.

Чаты и темы Telegram разделены namespace с префиксом `vpg08-team`. Пространства предыдущих уроков не используются. Ответы бота и команды в память не записываются. Вопрос через обычное @упоминание сохраняется как исходное сообщение пользователя, но исключается из контекста ответа на этот же вопрос.

## Запуск

Нужны Python 3.13, Telegram-бот и готовый индекс Pinecone: **1536 измерений, cosine**. Индекс не создаётся приложением намеренно. Модель эмбеддингов должна выдавать 1536 измерений.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
cp .env.example .env
```

Заполните `.env`:

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Ключ провайдера моделей |
| `OPENAI_BASE_URL` | При необходимости URL совместимого API/прокси |
| `CHAT_MODEL` | Доступная у провайдера модель; при проверке `gpt-6-luna` |
| `EMBEDDING_MODEL` | `text-embedding-3-small` |
| `PINECONE_API_KEY`, `PINECONE_INDEX_NAME` | Доступ к существующему индексу |
| `TELEGRAM_BOT_TOKEN` | Токен учебного Telegram-бота |
| `ALLOWED_USER_IDS` | ID владельцев через запятую; разрешены личные чаты этих пользователей и команды управления |
| `ALLOWED_CHAT_IDS` | ID явно разрешённых групп через запятую |

```bash
python bot.py
```

Точка входа использует файловую блокировку `fcntl` (macOS/Linux), чтобы не запускать два учебных бота с одним токеном. Активный webhook не удаляется автоматически. Старые накопленные Telegram updates при старте пропускаются; бот обрабатывает новые сообщения после запуска. Остановите процесс `Ctrl+C`.

### Групповая проверка

Создайте отдельную учебную группу и добавьте бота. Владелец из `ALLOWED_USER_IDS` может вызвать `/id@имя_бота`, чтобы узнать ID даже до добавления группы в список разрешённых. Добавьте ID в `.env` и перезапустите процесс. `/id` не включает сбор данных.

Telegram должен передавать боту обычные сообщения группы: это зависит от Privacy Mode и административного статуса. Перед стартом групповой сессии приложение проверяет доступ. При отсутствии доступа оно откажется начинать заведомо неполную запись и объяснит причину. Настраивайте права только в согласованной учебной группе; для реальных обсуждений участники должны знать о передаче текста и авторства внешним сервисам.

Пример обсуждения:

```text
/start_listening@имя_бота
Анна: Предлагаю демонстрацию в четверг в 11:00, бюджет 18000 рублей.
Борис: Предлагаю пятницу в 15:30. Подготовлю стенд.
Анна: Согласна, четверг отменяем. Бюджет теперь 12500 рублей.
@имя_бота Что думаешь?
/stop_listening@имя_бота
```

Имена в этом примере обозначают разных отправителей, а не специальный синтаксис команды. Бот берёт настоящего автора из Telegram update.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка |
| `/id` | ID чата и темы, только для владельца |
| `/start_listening` | Начать сессию, только для владельца |
| `/stop_listening` | Закончить сессию и получить итог, только для владельца |
| `/ask вопрос` | Вопрос по переписке |
| `/status` | Число сообщений, очередь индексации, состояние сессии |
| `/sync` | Повторить отправку очереди в Pinecone, только для владельца |

В группе бот также отвечает при @упоминании и ответе на его сообщение. В личном чате предусмотрено обращение «Что думаешь?». На обычную реплику он молча сохраняет контекст.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m pip check
```

Локальные тесты подменяют сетевые вызовы и проверяют хронологию, границы сессии, повторную доставку, восстановление после перезапуска/сбоя, очередь индексации, разрешения, Privacy Mode и обработчики Telegram.

Реальная проверка OpenAI/Pinecone с вымышленным обсуждением:

```bash
python scripts/verify_live.py
```

Этот скрипт расходует API-запросы, создаёт уникальное тестовое пространство Pinecone и сохраняет обезличенный результат в [evidence/live-results.json](evidence/live-results.json). Проверяются новое время и бюджет, распределение задач между двумя авторами, неизвестный адрес, изоляция другого чата и поиск из архива без локального журнала. Живую проверку Telegram и проверку сервиса через CLI нужно различать; JSON-протокол содержит именно CLI/API-проверку.

9 ноября 2026 года также проведён живой тест через Telegram Desktop: обычные сообщения, @упоминание «Что думаешь?», завершение сессии, память после перезапуска и отказ выдумывать неизвестный адрес. Проверка выполнена в отдельной учебной группе с одним человеческим аккаунтом и ботом. Два разных автора проверены отдельно через CLI. Обезличенная сводка: [evidence/telegram-checks.json](evidence/telegram-checks.json); скриншоты и реальные ID в репозиторий не включены. Временный процесс после проверки остановлен.

## Файлы

- `bot.py` - транспорт Telegram и контроль доступа.
- `service.py` - запись, поиск, ответы и сессии.
- `storage.py` - SQLite, хронология и очередь индексации.
- `pipelines.py` - три графа Haystack.
- `config.py` - настройки без вывода секретов.
- `cli.py` - запуск тех же операций без Telegram.
- `tests/`, `scripts/verify_live.py` - локальные и реальные API-проверки.

## Ограничения

Это учебный прототип. Обрабатываются новые текстовые сообщения; файлы, голос, редактирование и удаление старых сообщений не синхронизируются. Анонимные сообщения от имени канала пропускаются. Миграция обычной группы в supergroup требует обновить разрешённый ID и начинает отдельную память. Автоматического переноса старого namespace нет.

Контекст одного запроса ограничен 120000 символов JSON; при превышении бот явно сообщает об ограничении и сохраняет журнал. Не реализованы бесконечный контекст и автоматическая иерархическая суммаризация. Общение с внешними сервисами синхронное: один медленный запрос задерживает обработку следующих updates. Pending-очередь повторяется при активности или `/sync`, фонового worker нет. Запись Pinecone становится доступна поиску с задержкой; последние сообщения доступны сразу через SQLite.

SQLite хранит человеческие сообщения локально; текст, авторство и служебные метаданные отправляются провайдерам эмбеддингов/генерации и Pinecone. Namespace изолирует поиск в приложении, но не заменяет права доступа к самому аккаунту Pinecone. Удаление локального файла SQLite не удаляет векторы из Pinecone. Политика срока хранения и интерфейс удаления не реализованы.

`.env`, базы, окружение, реальные Telegram-данные и снимки экрана не входят в репозиторий. Опубликованные примеры обсуждений вымышлены. Ответы модели могут содержать ошибки; проверка на нескольких примерах не гарантирует полноту поиска в большом архиве.
